## 1. 文档说明

### 1.1 编写目的

本文档定义智慧校园学生智能体系统的产品边界、业务流程、功能需求、数据需求、AI 行为约束、非功能需求和验收标准，是后续原型设计、系统设计、开发、测试和验收的统一依据。


### 1.2 需求约定

- `必须`：产品验收不可缺少的能力。
- `应`：正常交付应满足，确有约束时需记录替代方案。
- `可`：增强体验的能力，不得影响必须项交付。
- P0、P1、P2 仅用于实施顺序和风险管理，不代表拆分为多个产品版本。
- 所有需求均属于最终成品范围，变更必须保留原因、影响和验收记录。

## 2. 项目概述

### 2.1 产品定位

系统是一套面向在校学生的智慧校园 AI 助手。学生通过表单或自然语言描述目标，系统结合学生授权数据、食堂数据、考试记录、图书馆馆藏和校园知识库进行检索与分析，生成可解释、可追踪的个性化建议。本项目当前属于软件工程课设，首先保证本地开发、测试和课堂展示完整可用，不按工业级生产系统进行过度设计。

### 2.2 建设目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G-01 | 统一学生入口 | 一个账户访问全部四项学生服务 |
| G-02 | 个性化推荐 | 建议能够体现用户约束、偏好和已有数据 |
| G-03 | 结果可解释 | 展示推荐理由、关键依据和必要的资料来源 |
| G-04 | AI 可选择 | 学生可使用基础记录/查询，也可主动启用 AI 分析 |
| G-05 | 安全可信 | 敏感数据经授权使用，低置信度结果明确提示 |
| G-06 | 易开发与演示 | 优先保证本地运行、课堂演示和后续功能扩展 |

### 2.3 范围内能力

1. 学生使用学号、手机号、姓名等身份信息注册，随后通过账号密码登录、退出并管理个人资料、偏好和授权。
2. 录入并维护食材、菜品、价格、口味、营养、过敏原和供应状态数据。
3. 根据学生提出的口味、价格、营养、忌口等条件推荐餐食。
4. 使用简单考试安排表记录科目、考试时间和备注，系统自动排序并突出最近考试。
5. 学生主动请求后，AI 通过追问和工具调用收集规划信息，生成复习计划书、题目或资料建议。
6. 保存学校图书馆馆藏数据，根据用户条件推荐校内或未收录书籍。
7. 建设校园资料知识库，通过检索增强生成提供带来源的准确问答。
8. 使用统一信息资料管理系统录入和维护食堂、图书、知识文档、账号与必要配置，并尽可能保证信息完整。



## 3. 用户与权限

| 角色 | 主要职责 | 数据范围 |
|---|---|---|
| 学生 | 使用四项核心服务，维护个人记录、偏好和授权 | 仅本人数据及公开校园信息 |
| 信息资料管理员 | 通过一个统一管理系统维护食堂、食材、图书、馆藏、校园资料、账号和必要配置 | 全部管理数据，不能查看学生私密对话正文和未授权个人信息 |

信息资料管理员在同一个后台完成所有资料维护，不再按食堂、图书和知识库拆分多个管理员。录入页面应根据资料类型提供尽可能全面的字段、完整性提示和校验规则，减少因信息缺失影响 AI 推荐与问答质量。


## 4. 总体业务流程

### 4.1 通用 AI 处理流程

1. 学生登录后选择服务或直接输入自然语言请求。
2. 系统识别意图，加载当前用户、授权范围和业务上下文。
3. 条件不充分时，AI 主动提出少量必要问题；能够从已有数据取得的信息不重复询问。
4. 系统调用受控工具检索业务数据库或知识库。
5. 推荐或回答模块依据约束、适配度和证据生成结果。
6. 页面展示结论、理由、来源、不确定性和可执行的下一步。
7. 系统保存必要的请求摘要、工具调用和结果版本，支持审计与反馈。

### 4.2 关键业务原则

- 业务数据库是菜品、考试、馆藏和校园资料的事实来源，大模型不得编造数据库状态。
- AI 可以分析和建议，不得绕过权限直接修改学生记录或管理数据。
- 影响个人偏好、学习计划或长期记忆的写入必须由学生确认。
- 当数据缺失、冲突或过期时，系统必须说明限制并提供补充信息入口。

### 5.3 学生智能食堂推荐

#### 5.3.1 场景说明

学生可用自然语言或筛选表单提出餐食要求，例如“20 元以内、微辣、高蛋白、不要花生、午餐不要太油”。系统结合已录入的食材、菜品、营养、过敏原、价格和当日供应状态，筛选硬约束并按适配度推荐餐食。

#### 5.3.2 典型流程

1. 学生输入用餐时段、预算、口味、营养目标、忌口或其他要求。
2. 系统读取学生已授权偏好，并对缺失的关键条件进行询问。
3. 系统检索当日可供应菜品及食材信息，先过滤过敏原、忌口、预算上限等硬约束。
4. 系统根据口味、价格、营养、热量、供应和历史反馈计算适配度。
5. 系统返回单品或套餐，展示价格、营养、主要食材、匹配理由和风险提示。
6. 学生可调整条件、比较方案或反馈结果。

### 5.4 考试安排记录与 AI 学习规划

#### 5.4.1 场景说明

考试安排表是一个不依赖 AI 的简单记录工具。学生只需填写考试科目、考试时间和备注，系统自动按时间排序并突出显示距离当前时间最近的考试。只有当学生主动使用“AI 制定复习计划”时，AI 才进入流程，通过追问和工具调用收集考试难度、复习范围、掌握情况、可用时间和目标等信息，生成对应的复习计划书，并可补充题目或资料建议。

#### 5.4.2 考试安排记录表

| 字段 | 必填 | 说明 |
|---|---|---|
| 考试科目 | 是 | 学生可识别的科目或考试名称 |
| 考试时间 | 是 | 日期和时间，用于自动排序和识别最近考试 |
| 备注 | 否 | 学生自行填写的地点、范围或其他简单说明，系统不要求结构化拆分 |

#### 5.4.3 典型流程

基础记录流程：

1. 学生填写考试科目、考试时间和可选备注后保存。
2. 系统按考试时间升序显示全部未结束考试。
3. 系统在首页和考试页面突出显示最近一场考试及剩余时间。
4. 学生可编辑或删除本人记录；整个过程不调用 AI。

AI 复习计划流程：

1. 学生选择一个或多个已记录考试，主动点击“AI 制定复习计划”。
2. AI 读取选中的考试科目、时间和备注，并主动询问难度、范围、掌握情况、每天可用时间、目标和复习偏好等必要信息。
3. 对已有且经授权的数据，AI 可调用考试查询、资料检索、书籍检索和计划计算等工具，避免重复询问。
4. AI 根据考试先后、剩余时间、难度、掌握情况和可用时间制定复习优先级与计划书。
5. MVP 阶段返回结构清晰的基础计划书，并允许学生保存、查看、删除或重新生成。
6. AI 可按需要调用知识库和书籍工具，提供相关题目、解析或资料建议。

| 需求编号 | 优先级 | 需求说明 | 验收要点 |
|---|---|---|---|
| FR-EXAM-001 | P0 | 学生可使用科目、考试时间和备注新增、查看、编辑和删除本人考试记录 | 仅科目和时间必填，数据隔离与日期校验正确 |
| FR-EXAM-002 | P0 | 系统自动按考试时间升序排列未结束考试 | 新增或修改后排序立即更新，已过期记录不影响最近考试判断 |
| FR-EXAM-003 | P0 | 首页和考试页面显示最近一场考试及剩余时间 | 最近考试与当前有效记录一致 |

| FR-EXAM-013 | P0 | 系统不得保证分数或代替学生完成考试和作业 | 计划页面展示学术诚信与结果仅供参考提示 |

#### 5.4.5 后续扩展方向（不纳入 MVP 必验）

后续可将计划书升级为可交互实例，例如将计划拆分为可勾选任务、记录完成进度、根据实际完成情况调整剩余计划、发送提醒和展示进度统计。MVP 只要求生成和管理基础计划书，不要求任务勾选、自动进度跟踪和动态重排。

### 5.5 学校书籍查询与 AI 推荐

#### 5.5.1 场景说明

学生可输入主题、用途、专业、关键词、难度、语言、作者或书名等信息。系统结合图书元数据与馆藏状态计算适配度，优先推荐学校图书馆已收录的书籍；若馆藏中没有足够合适的结果，可明确推荐未收录书籍，或同时展示馆藏与馆外两组结果。

#### 5.5.2 典型流程

1. 学生输入书籍名称、作者、ISBN、关键词或自然语言需求。
2. 系统识别主题、用途、难度、语言、版本和馆藏偏好。
3. 系统检索本地图书与馆藏数据库，形成馆藏候选集。
4. 必要时检索允许使用的外部书目数据，形成未收录候选集。
5. 系统按内容适配度、馆藏可用性、难度和版本等因素排序。
6. 页面明确区分“馆藏已有”和“图书馆未收录”，并说明推荐理由。

#### 5.5.3 详细需求

| 需求编号 | 优先级 | 需求说明 | 验收要点 |
|---|---|---|---|
| FR-BOOK-001 | P0 | 信息资料管理员维护书名、作者、ISBN、出版社、版本、年份、语言、简介和主题标签 | ISBN 和版本可区分，必填字段校验生效 |
| FR-BOOK-002 | P0 | 维护馆藏位置、索书号、馆藏数量、可用数量和状态 | 推荐详情展示最新馆藏状态与更新时间 |
| FR-BOOK-003 | P0 | 支持书名、作者、ISBN、关键词和主题的组合查询 | 精确条件优先，结果可排序和筛选 |
| FR-BOOK-004 | P0 | AI 从自然语言识别学习主题、用途、难度、语言和版本偏好 | 解析条件可见并允许修正 |
| FR-BOOK-005 | P0 | 信息不足时 AI 可询问用途、基础水平或馆藏偏好 | 已有条件不重复询问 |
| FR-BOOK-006 | P0 | 推荐排序优先考虑内容适配度，在适配度相近时优先馆藏已有且可用的书籍 | 测试数据下排序符合规则 |
| FR-BOOK-007 | P0 | 馆藏没有足够合适结果时可推荐未收录书籍 | 未收录状态醒目标识，不展示虚假索书号 |
| FR-BOOK-008 | P0 | 可同时展示馆藏推荐和未收录推荐，并分别排序 | 两组来源和状态清晰可辨 |
| FR-BOOK-009 | P0 | 每项推荐展示匹配主题、适用人群、难度、版本和推荐理由 | 理由与用户需求相对应 |
| FR-BOOK-010 | P1 | 学生可收藏、隐藏和反馈推荐结果 | 反馈与用户和结果版本关联 |
| FR-BOOK-011 | P1 | 馆藏数据支持批量导入、增量更新和异常校验 | 重复 ISBN/馆藏记录进入待处理清单 |
| FR-BOOK-012 | P0 | 外部书目信息记录来源和获取时间 | 来源不可用时不影响馆藏查询 |

### 5.6 校园知识问答

#### 5.6.1 场景说明

学生可询问学校规章、办事流程、校园服务、活动通知、场所信息等问题。系统从经过审核的校园资料数据库中检索相关片段，基于证据生成准确回答，并展示文档名称、章节、更新时间和原文定位。

#### 5.6.2 典型流程

1. 学生输入问题，系统进行问题规范化和意图识别。
2. 系统按用户权限、文档状态、有效期和适用范围过滤知识。
3. 系统执行关键词与向量混合检索并进行重排序。
4. AI 仅基于检索证据生成回答，展示引用和原文入口。
5. 无充分证据、资料冲突或资料过期时，系统说明情况并建议咨询渠道。
6. 学生可反馈回答错误、无帮助或资料过期。

#### 5.6.3 详细需求

| 需求编号 | 优先级 | 需求说明 | 验收要点 |
|---|---|---|---|
| FR-QA-001 | P0 | 支持 Markdown、TXT资料导入 | 导入失败可定位文件和原因 |
| FR-QA-002 | P0 | 解析标题、正文、表格和页码并保留原文定位 | 检索片段可回到正确文档位置 |
| FR-QA-003 | P0 | 维护文档类别、责任部门、适用对象、有效期、版本和权限 | 缺少必要元数据不得发布 |
| FR-QA-004 | P0 | 支持草稿、待审核、已发布、已驳回和已失效状态 | 仅已发布且有效资料进入默认检索 |
| FR-QA-005 | P0 | 使用关键词与向量混合检索并支持结果重排序 | 标准问题集检索召回达到验收指标 |
| FR-QA-006 | P0 | 回答前按身份、权限和资料适用范围过滤 | 无权内容不出现在片段、答案和日志明文中 |
| FR-QA-007 | P0 | 事实性回答必须至少包含一个有效引用 | 引用包含文档名、章节/页码和更新时间 |
| FR-QA-008 | P0 | 无充分证据时拒绝编造并说明缺失信息 | 不输出虚构的制度、时间、地点或联系方式 |
| FR-QA-009 | P0 | 资料冲突时展示冲突来源并优先采用最新有效正式版本 | 无法判断时提示责任部门确认 |
| FR-QA-010 | P1 | 学生可提交错误、过期、缺失和无帮助反馈 | 反馈生成待办并可追踪处理状态 |

### 5.7 统一信息资料管理

食堂、图书、知识库、账号和必要系统配置由一个统一的信息资料管理后台维护。课设阶段只设置一种信息资料管理员角色，不拆分多个管理系统。管理表单应尽可能全面录入可获得的信息，并通过必填项、格式校验和完整性提示帮助管理员补充资料。

| 需求编号 | 优先级 | 需求说明 | 验收要点 |
|---|---|---|---|
| FR-ADM-001 | P0 | 提供一个统一信息资料管理后台，集中管理食堂、食材、图书、馆藏、校园资料、账号和必要配置 | 管理员登录一次即可在统一导航中维护全部信息类型 |
| FR-ADM-002 | P0 | 系统仅设置一种信息资料管理员角色，并与学生权限隔离 | 学生不能进入后台，管理员不能越权读取学生私密内容 |
| FR-ADM-003 | P0 | 各类录入表单尽可能覆盖推荐和问答所需信息，并区分必填、推荐填写和可选字段 | 页面显示字段说明和资料完整度，缺少关键字段时提示补充 |
| FR-ADM-004 | P0 | 食材与菜品应尽量录入口味、价格、营养、过敏原、食材组成、窗口、供应状态和更新时间 | 信息可被食堂推荐工具正确检索和使用 |
| FR-ADM-005 | P0 | 图书与馆藏应尽量录入书名、作者、ISBN、版本、简介、主题、难度、索书号、位置和可用状态 | 信息可支持适配度分析和馆藏优先推荐 |

| FR-ADM-007 | P1 | 主要资料支持新增、编辑、删除/停用、搜索和批量导入 | 操作结果明确，格式错误可定位到具体记录 |

## 7. AI 推荐与问答规则

### 7.1 食堂推荐规则

- 硬约束：过敏原、明确忌口、不可供应、学生确认的价格上限。
- 软约束：口味、营养目标、热量偏好、距离、历史反馈和价格偏好。
- 先过滤硬约束，再对候选项评分；评分因素和权重必须可配置、可追踪。
- 无完全匹配时只允许放宽软约束，并明确展示被放宽内容。

### 7.2 学习规划规则

- 输入至少包括考试时间；难度、掌握情况和可用时间不足时应主动询问。
- 任务总时长不得超过学生填写的可用时间，必须预留休息和复盘时间。
- 多场考试按照紧迫度、难度、薄弱程度和目标综合排序，不得只按考试日期排序。
- 计划和练习题必须允许学生修改、拒绝、重新生成和反馈。

### 7.3 图书推荐规则

- 内容适配度是首要排序因素，馆藏可用性用于同等或相近适配度下优先排序。
- 馆藏书和未收录书必须分组或明确标识，不得虚构馆藏数量或位置。
- 未收录推荐必须包含书目信息来源和查询时间。

### 7.4 知识问答规则

- 事实性回答只使用已发布、有效且有权限的知识片段。
- 回答必须引用来源；引用与答案不能相互矛盾。
- 证据不足时回答“暂未查到充分依据”，并给出补充问题或咨询渠道。
- 模型不得把常识、推测或旧会话内容伪装为学校正式规定。

## 8. 用户界面需求

### 8.1 学生端页面

1. 身份入口页：学生注册、账号登录、字段校验、错误提示和隐私说明。
2. 首页：近期考试、今日学习任务、食堂推荐入口、图书查询和知识问答入口。
3. 智能食堂：自然语言输入、条件筛选、推荐卡片、对比和反馈。
4. 考试安排：科目、时间和备注录入，自动排序、最近考试展示以及主动触发的 AI 复习计划入口。
5. 书籍查询：搜索条件、馆藏/未收录分组、适配度和推荐理由。
6. 知识问答：流式回答、引用、原文入口、反馈和历史会话。
7. 个人中心：资料、偏好、授权、收藏、历史和数据清理。
8. 信息资料管理后台：以统一导航管理食堂、食材、图书、馆藏、校园资料、账号和必要配置，并显示信息完整度。

### 8.2 交互要求

- AI 解析出的条件必须以标签或表单形式展示并允许修改。
- 加载、排队、重试、降级和错误状态必须清晰，不得长期无反馈。
- 表单提供即时校验、防重复提交和未保存离开提示。
- 桌面端与主流移动浏览器均可使用，窄屏不得横向溢出核心内容。
- 颜色、状态和操作术语在所有模块保持一致，关键功能支持键盘操作。

- 后端和 AI 服务输出必要日志，能够定位到请求、模型调用、工具调用和数据库错误。
- 课设阶段使用控制台日志、结构化应用日志和简单健康检查即可，不要求建设独立监控告警平台。

| AT-14 | 知识不足或冲突 | 系统不编造，说明证据不足或冲突并给出咨询渠道 |
| AT-15 | 授权撤回 | 撤回敏感数据授权后停止用于新分析并清理长期记忆 |
| AT-16 | 模型故障降级 | 模型异常时基础记录、查询和关键词检索仍可使用 |
| AT-17 | 本地课堂演示 | 按启动文档在开发电脑运行全部服务，连续演示核心流程无明显卡顿或崩溃 |
| AT-18 | 重启与数据准备 | 应用重启后已保存记录仍存在，备份或初始化脚本可恢复课堂演示数据 |

## 13. 缺陷退出准则

| 级别 | 定义 | 验收要求 |
|---|---|---|
| S1 | 系统不可用、数据丢失、严重安全漏洞、越权或错误敏感推荐 | 必须为 0 |
| S2 | 核心流程不可完成、答案无依据、明显数据错误且无可接受绕行 | 必须为 0 |
| S3 | 非核心功能异常或存在可接受绕行方案 | 有确认的修复计划 |
| S4 | 轻微显示、文案或低影响体验问题 | 不影响验收，可进入维护清单 |

## 14. 风险、假设与依赖

| 编号 | 风险或依赖 | 应对措施 |
|---|---|---|
| R-01 | 食材和营养数据不完整 | 必填校验、来源记录、缺失标记和定期复核 |
| R-02 | 考试难度与掌握情况主观 | 主动追问、展示假设、允许学生调整和持续反馈 |
| R-03 | 馆藏状态更新不及时 | 增量同步、更新时间展示、异常对账和降级提示 |
| R-04 | 大模型生成不准确 | RAG、规则约束、引用、低置信度拒答和评估集 |
| R-05 | Agent 误用工具 | 工具白名单、独立权限校验、参数 Schema、超时和审计 |
| R-06 | 敏感数据泄露 | 单独授权、最小权限、加密、脱敏和受限导出 |
| R-07 | 本地环境和模型接口不稳定 | 固定依赖版本、提供环境检查、错误提示、重试和基础功能降级 |
| R-08 | 校园资料过期或冲突 | 责任部门、有效期、审核、版本和定期质量评估 |

## 15. 需求追踪与变更原则

- 每项功能需求必须关联设计项、代码模块、自动化测试和验收结果。
- 需求变更必须记录原因、影响模块、数据迁移、兼容性、测试范围和回滚方式。
- 涉及权限、隐私、推荐硬约束、事实来源和 Agent 工具的变更必须进行安全评审。


## 16. 术语

| 术语 | 定义 |
|---|---|
| Agent/智能体 | 能够理解目标、补充信息、规划步骤并调用受控工具完成任务的软件实体 |
| RAG | 先从受控知识库检索证据，再基于证据生成回答的技术 |
| 硬约束 | 不允许推荐结果违反的条件，例如过敏原、明确忌口和数据权限 |
| 软约束 | 可按优先级权衡的偏好，例如口味、预算偏好和难度偏好 |
| 适配度 | 候选结果与用户需求、数据状态和业务规则的综合匹配程度 |
| 馆藏已有 | 学校图书馆数据库中存在有效馆藏记录的书籍 |
| 未收录 | 当前学校图书馆数据库中不存在有效馆藏记录的书籍 |

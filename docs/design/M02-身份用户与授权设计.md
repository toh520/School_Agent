# M02 身份、用户与授权设计

## 1. 范围

本模块覆盖 FR-IAM-001～008、AT-01 和 AT-15，只实现学生注册、登录会话、本人资料、长期饮食安全档案、四类数据授权、授权撤回与长期记忆清理、角色边界和审计检索。资料后台、Agent 工作流及食堂、考试、图书、知识问答均不在本阶段实现。

## 2. 安全模型

- Java 服务是身份与权限的唯一可信入口；浏览器传入的用户 ID 不能决定本人数据范围。
- 密码使用 BCrypt 单向哈希。登录失败统一返回 `INVALID_CREDENTIALS`，避免枚举账号。
- 公开注册只创建学生角色；学号、手机号和不区分大小写的登录账号均由数据库唯一约束保护。
- 访问令牌为短期 HMAC-SHA256 JWT，包含用户 ID、角色和服务端会话 ID。
- 刷新令牌使用安全随机数，数据库只保存 SHA-256 摘要；刷新时轮换，退出时撤销会话。
- 每个受保护请求同时验证 JWT 与服务端会话，因此退出后尚未过期的访问令牌也立即失效。
- `EXAMS`、`MASTERY`、`DIET`、`CHAT_HISTORY` 四类授权默认均为未授权。
- 撤回授权在同一事务中更新授权、删除对应长期记忆并写入清理与审计记录。

## 3. 数据表

| 表 | 职责 |
|---|---|
| `app_user` | 账号、学号、姓名、手机号、角色、状态和非核心资料 |
| `user_preference` | 当前保存长期忌口和过敏原；历史口味、预算和饮食目标字段仅为迁移兼容保留，不再作为固定个人档案使用 |
| `data_authorization` | 四类 AI 数据使用授权 |
| `auth_session` | 可撤销、可轮换的刷新会话 |
| `user_long_term_memory` | 后续 Agent 可使用且受授权约束的长期记忆占位 |
| `data_cleanup_record` | 授权撤回或用户请求触发的清理结果 |
| `audit_event` | 登录、权限变化、敏感访问和清理审计 |

## 4. API 契约

| 方法与路径 | 认证 | 能力 |
|---|---|---|
| `POST /api/v1/auth/login` | 否 | 账号密码登录 |
| `POST /api/v1/auth/register` | 否 | 使用学号、手机号、姓名、账号和密码注册学生 |
| `POST /api/v1/auth/refresh` | 否 | 轮换刷新令牌 |
| `POST /api/v1/auth/logout` | 是 | 撤销当前会话 |
| `GET /api/v1/users/me` | 是 | 本人资料、偏好和授权汇总 |
| `PATCH /api/v1/users/me/profile` | 学生 | 修改非核心资料 |
| `PUT /api/v1/users/me/preferences` | 学生 | 保存长期过敏原和明确忌口；兼容字段在 M05 迁移前原样保留 |
| `PUT /api/v1/users/me/authorizations/{scope}` | 学生 | 独立授予或撤回数据授权 |
| `POST /api/v1/users/me/data-cleanup` | 学生 | 清理指定范围长期记忆 |
| `GET /api/v1/users/me/audit-events` | 是 | 查询本人审计记录 |
| `GET /api/v1/users/{userId}/profile` | 是 | 所有权边界验证；学生仅本人，管理员仅基本资料 |
| `GET /api/v1/admin/audit-events` | 管理员 | 按用户、时间、事件和模块检索审计 |

所有响应继续使用 M01 `ApiResponse`，401/403 也返回统一错误结构和 `X-Request-ID`。

注册事务同时创建 `app_user`、`user_preference` 和四项 `data_authorization`。注册成功后建立可撤销会话；并发重复注册最终由 V4 唯一索引兜底。

数据库表格查看与本地数据操作见 `M02-PostgreSQL表格操作指南.md`。表结构始终由 Flyway 管理。

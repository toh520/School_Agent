# M01 配置项与环境变量清单

本文档是智慧校园智能体系统的公共配置基线。后续编码应先在此登记配置项，再通过环境变量和服务配置对象读取，禁止把数据库地址、端口、用户名、密码、服务地址、密钥或部署域名直接写入业务代码。

## 1. 配置文件约定

| 文件 | 是否提交 Git | 用途 |
|---|---|---|
| `code/deploy/.env.example` | 是 | 提供变量名称、安全示例和默认本地端口，不包含真实凭据 |
| `code/deploy/.env.local` | 否 | 开发者本机真实配置，已由 `.gitignore` 忽略 |
| `code/services/core-service/src/main/resources/application.yml` | 是 | Java 配置映射，只引用环境变量 |
| `code/services/agent-service/src/agent_service/config.py` | 是 | Python 配置模型，只读取并校验环境变量 |
| `code/apps/web/vite.config.ts` | 是 | Web 开发代理配置，不保存密码或后端密钥 |

创建本地配置：

```powershell
Copy-Item code/deploy/.env.example code/deploy/.env.local
```

随后修改 `code/deploy/.env.local` 中的占位值。不得把该文件改成可提交状态。

## 4. 各端读取方式

### 4.1 Java

Java 使用 `application.yml` 将环境变量映射到 Spring 配置，并通过 `FoundationProperties`、`AuthProperties` 等配置类访问。业务类不得直接调用 `System.getenv()`；只有启动前配置预检组件可以检查环境变量是否存在。

```yaml
spring:
  datasource:
    url: ${SCHOOL_AGENT_DB_URL}
    username: ${SCHOOL_AGENT_DB_USERNAME}
    password: ${SCHOOL_AGENT_DB_PASSWORD}
```

正确方式：构造器注入配置类或 Spring 已配置的数据源。

错误方式：

```java
// 禁止：地址、用户和密码被硬编码。
DriverManager.getConnection(
        "jdbc:postgresql://127.0.0.1:5432/school_agent", "school_agent", "password");
```

### 4.2 Python

Python 使用 `agent_service.config.Settings` 统一读取和校验变量。敏感值使用 `SecretStr`，业务模块不得自行调用 `os.getenv()` 拼装数据库连接。

```python
from agent_service.config import get_settings

settings = get_settings()
database_host = settings.db_host
```

错误方式：

```python
# 禁止：连接信息被写死在代码中。
connection = psycopg.connect("postgresql://school_agent:password@127.0.0.1/school_agent")
```

### 4.3 Web 前端

浏览器请求统一使用相对地址 `/api/v1`，开发环境由 Vite 代理到 Java 服务。前端不得保存数据库配置、模型密钥、服务密钥或任何后端密码。

```typescript
const http = axios.create({ baseURL: '/api/v1' })
```

错误方式：

```typescript
// 禁止：组件中写死后端地址，切换环境时必须修改源码。
axios.get('http://127.0.0.1:8080/api/v1/health/system')
```

## 5. 新增配置项流程

后续模块需要新增配置时，必须按以下顺序处理：

1. 判断该值是否会随机器、环境或部署方式变化；会变化的值必须配置化。
2. 在 `code/deploy/.env.example` 添加变量名称和无敏感信息的示例。
3. 在本文档登记用途、使用方、是否必需和是否敏感。
4. 在 Java 配置类或 Python `Settings` 中集中读取并校验。
5. 为缺失值、非法值和默认值编写测试。
6. 更新 README、测试记录；影响公共契约时更新 M01 验收记录或建立变更记录。

## 6. 禁止硬编码清单

以下内容不得直接写入 Java、Python、TypeScript、SQL 迁移或测试快照：

- 真实数据库密码、模型 API Key、访问令牌和会话密钥；
- 个人电脑绝对路径，例如 `C:\Users\...`；
- 云服务器 IP、正式域名和正式数据库地址；
- 真实学生账号、联系方式、过敏信息或聊天正文；
- 只能在某台电脑使用的端口或文件目录。

允许出现在代码中的内容：

- 协议字段名、稳定错误码和公开接口路径；
- 项目确定的时区 `Asia/Shanghai`；
- 无敏感信息的测试夹具；
- 有明确配置覆盖方式的安全默认端口。

## 7. 安全检查

提交前至少执行：

```powershell
git status --short
git diff --check
git check-ignore code/deploy/.env.local
```

检查要点：

- `code/deploy/.env.local` 必须显示为被忽略；
- Git 差异中不得出现真实密码、令牌、密钥和个人绝对路径；
- 日志不得输出数据库连接串、密码或完整环境配置；
- 配置缺失时应快速失败，不得静默连接到其他数据库。

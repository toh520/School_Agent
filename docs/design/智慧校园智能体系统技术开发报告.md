# 智慧校园智能体系统技术开发报告

> 文档版本：V1.0  
> 编制日期：2026-08-28  
> 需求基线：`智慧校园智能体系统需求分析报告 V1.0`  
> 适用范围：系统设计、迭代开发、代码审查、测试与项目验收

## 1. 文档目的

本文档将已确认的需求转化为可执行的技术模块和开发阶段，明确各模块职责、接口边界、阶段交付物、审查点和退出条件。团队应以需求编号、Issue、代码、测试和验收证据之间的可追踪关系推进开发。

本项目是软件工程课设，技术方案以本地可运行、核心流程完整、数据安全、AI 结果可信和课堂演示稳定为优先目标，不引入超出实际需要的复杂基础设施。

## 2. 技术目标与设计原则

### 2.1 技术目标

1. 建立统一登录、权限、授权和审计能力，为全部业务模块提供安全基础。
2. 完成智能食堂、考试记录与学习规划、书籍查询推荐、校园知识问答四项学生服务。
3. 建立统一信息资料管理后台，保证食堂、图书和知识数据可维护、可校验、可追踪。
4. 将确定性业务规则与大模型生成能力分离，确保模型不可用时基础业务仍可使用。
5. 形成需求、设计、代码、测试和验收证据闭环，支持团队协作和最终答辩。

### 2.2 设计原则

- PostgreSQL 是业务事实数据源，AI 不得猜测或覆盖事实字段。
- Java 服务负责身份权限、业务数据、确定性规则和写入控制；Python 服务负责对话、检索、推荐和 Agent 编排。
- Agent 只通过受控工具接口访问业务能力，不直接修改核心业务表。
- 所有个人数据按用户隔离；敏感信息必须先授权、后使用，并记录审计事件。
- 推荐先执行硬约束过滤，再执行软约束评分；任何降级不得放宽安全和权限约束。
- AI 输出必须呈现依据、来源、关键假设和不确定性。
- 每个模块均按 D1～D6 步骤推进，当前模块满足门禁后才能进入下一模块；只允许当前模块内部按技术层分工，不得并行开发多个功能模块。

## 3. 总体技术架构

```text
学生端 / 信息资料管理端（Vue 3 + TypeScript）
                    │ HTTP JSON / SSE
                    ▼
      Java 核心业务服务（Spring Boot）
  认证授权、资料管理、业务数据、审计、受控工具
          │                      │
          │ REST                 │ SQL
          ▼                      ▼
 Python Agent 服务          PostgreSQL + pgvector
意图识别、推荐、规划、RAG      事实数据、向量、调用轨迹
          │
          ▼
     大模型适配层 / Embedding 服务
```

### 3.1 运行边界

| 层级 | 技术 | 核心责任 | 禁止事项 |
|---|---|---|---|
| Web 前端 | Vue 3、TypeScript、Vite、Element Plus、Pinia | 页面、表单、状态、错误反馈、SSE 展示 | 不在前端实现可信权限判断或保存密钥 |
| Java 业务服务 | Java 21、Spring Boot 3.5、Spring Security、MyBatis-Plus | 认证、授权、事务、业务数据、后台、审计、工具接口 | 不把核心业务校验交给前端或模型 |
| Python Agent | Python 3.11/3.12、FastAPI、LangGraph | 对话、意图、条件提取、推荐编排、学习规划、RAG | 不直连核心表执行写入，不绕过授权 |
| 数据层 | PostgreSQL、pgvector、本地受控文件目录 | 事实数据、关系数据、向量、文件元数据 | 不保存明文密码、令牌或未脱敏敏感日志 |
| 测试层 | JUnit、pytest、Playwright、接口测试 | 单元、集成、契约、端到端和验收测试 | 不仅依赖人工演示判断完成状态 |

## 4. 按功能划分的项目模块

### 4.1 划分原则

项目以需求分析报告中的需求域为主要模块边界。每个业务模块应形成从数据、Java 确定性业务、受控工具、Python Agent 编排、前端页面到自动化测试的完整纵向切片，完成本模块退出条件后再进入下一个模块。公共能力不在业务模块中重复实现。

- M01～M04 为公共基础模块，先建立工程、身份、资料维护和 Agent 底座。
- M05～M08 为四个可独立演示、独立验收的核心业务模块。
- M09、M10 为业务模块完成后的质量整合与最终交付模块，分别安排独立开发阶段。
- 需求编号只归属一个主要功能模块；跨模块约束通过依赖关系和契约测试处理。
- 每个模块必须同时交付实现、测试、文档和过程证据，不能只完成页面或接口之一。
- 开发阶段与模块一一对应；一个阶段只能开发一个模块，不得同时推进其他模块的新增功能。

### 4.3 M01 工程基础与公共规范

**模块目标**：建立所有模块共享且可重复运行的工程骨架，避免后续各功能自行定义配置、错误、日志和测试方式。

**功能范围**：

- 创建 Vue、Spring Boot、FastAPI 三端工程和 PostgreSQL/pgvector 数据环境。
- 统一环境变量、配置分层、响应结构、错误码、请求标识、时区和分页结构。
- 建立数据库迁移、脱敏初始化数据、健康检查、日志脱敏和异常处理。
- 建立 JUnit、pytest、Playwright、静态检查、格式化和构建命令。
- 提供本地启动、停止、环境检查和故障定位说明。

**建议目录**：

```text
School_Agent/
├─ code/                     # 开发代码、测试与工程脚本
│  ├─ apps/web/              # 学生端与统一管理端
│  ├─ services/core-service/ # Java 核心业务服务
│  ├─ services/agent-service/# Python Agent 服务
│  ├─ tests/                 # 契约、端到端、性能和安全测试
│  ├─ tools/                 # 环境检查、初始化和校验脚本
│  └─ deploy/                # 本地数据库和可选部署配置
└─ docs/                     # 需求、设计、决策与过程证据
```

**主要交付物**：三端工程、迁移脚本、`.env.example`、启动说明、统一错误规范、健康接口和冒烟测试。

**退出条件**：另一名成员可仅根据 README 在新环境启动系统；浏览器—Java—Python—数据库健康链路通过；仓库和日志无真实密钥；各端至少一个自动化冒烟测试通过。

### 4.4 M02 身份、用户与授权

**模块目标**：为所有业务提供可信身份、用户数据隔离和 AI 数据授权边界。

**子功能**：认证会话、令牌刷新与退出、学生资料、个人偏好、敏感数据授权、授权撤回、数据清理、角色权限和登录审计。

**关键实现边界**：

- Java 服务是身份和权限判定的唯一可信入口。
- 所有本人数据查询必须绑定认证上下文，禁止信任请求传入的 `userId`。
- 考试、学习掌握、饮食和历史会话授权分别记录，默认未授权。
- 撤回授权后，新 Agent 任务立即停止加载对应数据；长期记忆清理过程可追踪。
- 密码使用强单向哈希，令牌、密码和敏感字段不得写入日志。

**主要交付物**：认证接口、权限过滤器、用户与授权数据模型、个人中心页面、权限测试、双用户越权测试和审计记录。

**退出条件**：FR-IAM-001～008 均有实现与测试映射；AT-01、AT-15 通过；身份与数据隔离相关 S1/S2 缺陷为 0。

### 4.5 M03 统一信息资料管理

**模块目标**：使用一个管理员角色和一个后台维护食堂、图书、校园公告、账号及必要配置，为后续业务模块提供可信测试数据和事实数据。

**子功能**：统一导航、分类 CRUD、批量导入、预校验、重复检测、完整度提示、确认入库、错误清单、停用/逻辑删除和基础操作记录。

**本模块完整范围**：

1. 实现统一后台骨架、管理员权限和通用表格、表单、搜索及导入能力。
2. 一次性完成食堂、窗口、食材、菜品、营养、过敏原和供应资料维护。
3. 一次性完成书目、版本、标签、馆藏和外部来源资料维护。
4. 完成校园公告标题、类别、检索关键词、正文和信息来源维护，为后续 RAG 提供简单、明确的文本语料。
5. 本阶段只开发资料管理能力，不实现食堂推荐、图书推荐或知识问答业务逻辑。

**关键实现边界**：管理员不得查看学生私密对话正文和未授权个人信息；导入文件和字段均视为不可信输入；事实字段不得由 AI 生成内容覆盖。

**主要交付物**：统一后台、管理接口、数据校验规则、导入模板、错误清单、完整度计算和管理操作日志。

**退出条件**：FR-ADM-001～008 完成；各业务模块需要的脱敏数据可通过后台或初始化脚本建立；错误记录能够定位到具体字段或导入行。

### 4.6 M04 通用 Agent 平台

**模块目标**：提供四项业务共用的对话、意图、追问、工具、安全和流式输出能力，业务模块只实现领域节点与领域结果。

**通用流程**：

```text
接收请求 → 识别意图 → 检查身份与授权 → 加载上下文
        → 补充必要条件 → 调用受控工具 → 生成结构化结果
        → 展示依据与限制 → 保存轨迹和反馈
```

**子功能**：多轮会话、四类意图识别、必要追问、条件结构化、工具注册、工具调用、SSE、超时与重试、模型降级、结果版本、长期偏好确认和用户反馈。

**工具契约最低字段**：工具名、版本、用途、输入 Schema、输出 Schema、所需权限、数据授权、超时、读写级别、幂等要求、错误类型和审计字段。

**关键实现边界**：Agent 不直接写核心表；权限和参数校验不能只依赖模型判断；未确认推断不得写入长期记忆；异常不得造成错误写入；证据不足必须表达不确定性。

**主要交付物**：LangGraph 基础工作流、模型适配层、工具注册表、授权上下文、SSE 接口、通用对话页面、降级策略、轨迹记录和固定评估集。

**退出条件**：FR-AGT-001～010 完成；四类意图标准集准确率不低于 90%；正常依赖下工具任务成功率不低于 95%；非法参数和越权工具调用均被阻止。

### 4.7 M05 智能食堂

**模块目标**：基于真实菜品和学生约束生成安全、可解释的单品或套餐推荐。

**纵向功能组成**：

- 基础数据：使用 M03 已完成的食堂、窗口、食材、菜品、营养、过敏原、价格和供应资料；本模块不再开发管理后台。
- Java 业务：组合查询、硬约束过滤、套餐营养与价格合计、规则评分、推荐结果与反馈保存。
- Agent 能力：自然语言条件提取、必要追问、候选工具调用、推荐解释和无完全匹配说明。
- 前端：条件表单、解析标签、推荐卡片、单品/套餐详情、替换选项和反馈。
- 测试：过敏原、忌口、停供、硬预算、缺失营养、条件冲突、套餐合计和模型降级。

**核心规则**：硬约束过滤必须由确定性代码执行且不得降级放宽；AI 只负责条件提取与解释。无完全匹配时只能放宽软条件，并明确显示放宽内容。

**主要交付物**：食堂领域模型、查询与推荐接口、Agent 食堂工作流、学生推荐页面、管理数据契约回归测试和 AT-02～04 证据。

**退出条件**：FR-FOOD-001～015 完成；AT-02～04 通过；过敏原、明确忌口和越权违反率为 0；模型关闭时仍可进行结构化查询和规则筛选。

### 4.8 M06 考试与学习规划

**模块目标**：提供完全不依赖 AI 的考试记录，并在学生主动触发后生成可执行的基础复习计划书。

**纵向功能组成**：

- Java 业务：科目、时间、备注 CRUD，未结束考试排序，最近考试和剩余时间，计划书保存/查看/删除/重新生成。
- Agent 能力：读取选中考试，追问难度、范围、掌握情况、可用时间、目标和偏好，调用考试、资料、书籍和计划计算工具。
- 前端：考试表单、排序列表、最近考试卡片、主动触发入口、规划对话和计划书页面。
- 测试：时间边界、过期考试、跨用户访问、多考试优先级、总时长、模型关闭和学术诚信提示。

**核心规则**：基础考试页面不得自动调用模型；计划总时长不得超过学生可用时间；计划需说明优先级、假设和限制；题目与资料标明来源或 AI 生成属性。

**MVP 边界**：只实现计划书生成与管理，不实现任务勾选、自动进度跟踪、提醒和动态重排。

**主要交付物**：考试与计划数据模型、业务接口、计划计算工具、Agent 规划工作流、考试与计划页面以及 AT-05～09 证据。

**退出条件**：FR-EXAM-001～013 完成；AT-05～09 通过；模型不可用时考试记录、排序和最近考试正常工作；多考试计划不超过总可用时间。

### 4.9 M07 图书与馆藏推荐

**模块目标**：按内容适配度推荐书籍，并准确区分学校馆藏与未收录书籍。

**纵向功能组成**：

- 基础数据：使用 M03 已完成的书目、版本、标签、馆藏和外部来源资料；本模块不再开发管理后台。
- Java 业务：组合查询、馆藏状态、适配度基础评分、馆藏与馆外结果分组、收藏/隐藏/反馈和来源记录。
- Agent 能力：识别主题、用途、难度、语言、版本与馆藏偏好，必要追问并解释排序原因。
- 前端：组合搜索、解析条件、馆藏/未收录分组、状态与更新时间、详情和反馈。
- 测试：重复 ISBN、不同版本、无馆藏、馆藏不可用、外部来源异常、虚假位置防护和模型降级。

**核心规则**：内容适配度优先；适配度相近时优先馆藏已有且可用；本地数据库是馆藏状态唯一事实来源；未收录结果不得展示索书号、馆藏数量或位置。

**主要交付物**：书目与馆藏领域模型、查询和推荐接口、Agent 图书工作流、学生查询页面、管理数据契约回归测试以及 AT-10～12 证据。

**退出条件**：FR-BOOK-001～012 完成；AT-10～12 通过；推荐所示馆藏位置、数量和状态与数据库一致；外部服务不可用时本地馆藏查询不受影响。

### 4.10 M08 校园知识问答

**模块目标**：从 M03 当前有效的校园公告文本中检索证据，生成带公告标题、类别和来源的回答。

**纵向功能组成**：

- 基础数据：使用 M03 已完成的公告标题、类别、关键词、正文和来源；本模块不再开发管理后台。
- 语料处理：按数据库记录读取公告正文、分块、向量化，并保留公告记录标识。
- 检索服务：只检索当前有效记录，执行关键词/向量混合检索、重排序和冲突检测。
- Agent 能力：基于证据回答、引用组装、证据不足拒答、冲突展示和咨询渠道提示。
- 前端：问答、流式状态、引用展开、原文入口、历史和错误/过期反馈。
- 测试：无证据、公告冲突、停用记录、提示注入和模型降级。

**核心规则**：只有数据库中当前有效的公告片段进入回答上下文；公告内容只能作为证据，不能作为系统指令；事实性回答引用覆盖率必须为 100%；证据不足时不得补充模型常识冒充校方规定。

**主要交付物**：公告语料同步、知识索引、检索接口、RAG 工作流、问答页面、管理数据契约回归测试、标准问题集和 AT-13～14 证据。

**退出条件**：FR-QA-001～010 完成；AT-13、AT-14 通过；引用可定位正确公告记录；停用资料不出现在答案和引用中。

### 4.11 M09 审计、质量与可观测性

**模块目标**：为全部模块提供可定位、可复核且不泄露敏感信息的运行证据。

**功能范围**：请求标识、结构化日志、操作日志、工具调用、模型/提示/知识版本、结果版本、错误分类、耗时指标、健康状态、敏感信息脱敏和 AI 质量评估。

**实施方式**：前序模块只实现自身验收所需的基础日志和安全记录；进入 M09 阶段后，再集中完成跨服务链路追踪、统一指标、AI 版本评估、日志脱敏总审查和质量证据汇总。M09 不新增或修改 M01～M08 的业务功能。

**退出条件**：可以从用户请求追踪到 Java 接口、Agent、工具和数据库错误；日志不包含密码、令牌、密钥和未脱敏敏感正文；NFR 与 AT-15～18 有可复核证据。

### 4.12 M10 集成测试、演示与交付

**模块目标**：验证全部模块组合后仍符合需求基线，并形成其他成员可复现的课堂演示版本。

**功能范围**：契约测试、端到端测试、安全测试、性能检查、AI 质量评估、备份恢复、重启验证、演示数据、启动脚本、故障降级脚本、验收报告和材料归档。

**退出条件**：AT-01～18 均有环境、步骤、结果、证据和责任人；S1/S2 缺陷为 0；S3 有确认的修复计划；非原开发者可按文档启动和演示系统。

## 5. 单个模块内部任务流程

每个总体开发阶段只选择一个模块，并在该阶段内部按 D1～D6 六个步骤完成闭环。执行期间不得切换到另一个模块开发新增功能。若发现前置模块存在阻断缺陷，应暂停当前阶段，将缺陷作为前置模块的独立修复阶段处理并验收后，再恢复当前模块。

### D1：模块需求确认与任务拆分

- 从需求报告提取本模块需求编号、验收要点、NFR 和风险。
- 明确模块范围、不包含内容、依赖模块和跨模块契约。
- 为需求创建 Issue/任务，填写负责人、完成定义和验证方式。
- 将需求逐项展开到追踪矩阵，避免只记录需求编号范围。

**门禁**：需求覆盖率 100%，范围和依赖无未解释冲突，每项任务可验证。

### D2：模块设计与契约评审

- 设计领域模型、数据库表、索引、唯一约束、事务和迁移方案。
- 定义 Java API、内部工具 Schema、Agent 输入输出和前端状态模型。
- 明确身份、资源所有权、数据授权、事实来源、异常和降级行为。
- 高风险技术取舍写入 ADR；接口变更先更新契约测试。

**门禁**：数据与接口通过评审；正常、参数错误、未认证、无权限、冲突、超时和降级响应均有定义。

### D3：确定性业务与管理能力

- 优先实现数据库迁移、Java 领域规则、业务接口和后台资料维护。
- 实现无模型条件下可使用的查询、记录、过滤或检索能力。
- 补充单元测试、数据库集成测试、权限测试和边界测试。
- 验证失败回滚、重复提交和并发更新不会产生半条数据。

**门禁**：确定性规则自动化测试通过；无模型时基础业务可用；数据和权限缺陷达到模块退出要求。

### D4：Agent 与 AI 能力

- 在 M04 基础上实现本模块意图、条件提取、必要追问和领域工作流。
- 通过 `/internal/tools` 调用业务能力，不直接访问或修改核心业务表。
- 实现结构化结果、依据、来源、假设、不确定性和降级结果。
- 建立固定测试集，记录模型、提示、工具和数据版本。

**门禁**：工具权限、硬约束、引用/事实和异常降级测试通过；AI 不覆盖事实数据。

### D5：前端集成与端到端验证

- 完成当前模块所属页面，覆盖加载、空数据、成功、错误、权限不足和降级状态；统一资料管理页面只在 M03 阶段开发。
- 展示 AI 解析条件并允许修正；关键写入防重复提交。
- 执行模块端到端场景、响应式检查和非开发者操作验证。
- 修复 S1/S2 缺陷并记录 S3/S4 处理结论。

**门禁**：本模块对应 AT 场景通过；主流程可由非开发者按脚本完成；无阻断缺陷。

### D6：模块验收与留痕关闭

- 更新需求追踪矩阵、测试日志和项目日志。
- 在 PR 中记录需求范围、接口/数据/权限影响、测试命令与结果。
- 更新 README、接口文档、数据字典和相关 ADR。
- 为下一模块确认可复用接口、数据和遗留风险。

**门禁**：实现、测试、文档、评审和证据齐全，满足 Definition of Done 后模块状态才能改为“已验收”。

4. 编写正常流程、异常降级和安全边界三类课堂演示脚本。
5. 完善 README、启动/停止手册、恢复手册、用户说明和已知限制。
6. 汇总测试日志、追踪矩阵、项目日志、ADR、会议纪要和验收报告。
7. 检查投屏环境不会显示密钥、后台敏感配置或真实个人数据。
8. 冻结最终演示版本并备份源码、迁移脚本、初始化数据和文档。

**不得开展**：任何模块新增功能。发现业务缺陷时记录归属；S1/S2 缺陷必须暂停 S10，并为所属模块建立独立修复阶段，修复验收后重新执行 S10。

**退出条件**：AT-01～18 全部有证据；S1/S2 为 0；S3 有确认计划；非原开发者可按文档复现并完成演示。

### 6.1 串行执行规则

1. 同一时间只能有一个阶段处于“开发中”。
2. 当前阶段只允许修改本模块代码、测试和直接相关文档。
3. 前置模块接口原则上冻结；需要不兼容变更时，暂停当前阶段并单独处理前置模块变更。
4. 当前模块完成 D6 留痕和评审后，下一模块才能从“待设计”改为“开发中”。
5. 修复阶段也只能对应一个缺陷归属模块，不得借修复同时扩展其他模块。
6. S10 只负责集成、验收和交付，不以“顺手修改”方式继续开发业务功能。

## 7. 通用代码审查清单

每个 Pull Request 除阶段专属审查点外，至少检查以下内容：

### 7.1 需求与范围

- [ ] PR 关联需求编号、Issue 和明确的完成定义。
- [ ] 改动只覆盖声明范围；非目标变更已拆分或解释。
- [ ] 需求、接口、数据或权限发生变化时已同步更新文档和追踪矩阵。

### 7.2 设计与代码质量

- [ ] 模块职责清晰，无跨层绕过或重复实现核心规则。
- [ ] 公共接口、复杂算法、安全边界和失败策略有必要说明。
- [ ] 无无理由的超长文件、超长函数、深层嵌套或大段复制代码。
- [ ] 异常被正确分类、转换和记录，不吞掉错误或暴露内部细节。

### 7.3 数据与兼容性

- [ ] 数据迁移兼容已有数据，约束和索引与访问方式匹配。
- [ ] 写操作具备事务、幂等或重复提交保护。
- [ ] 删除、撤回和失败清理行为符合数据保护要求。
- [ ] API 变更已评估前端、Java、Python 和测试的兼容性。

### 7.4 安全与 AI 边界

- [ ] 服务端执行身份、角色、资源所有权和数据授权校验。
- [ ] 输入、上传文件、模型输出和外部数据均视为不可信内容。
- [ ] 密钥、令牌、密码和敏感个人信息未进入代码、响应或日志。
- [ ] Agent 未绕过工具接口；AI 输出未直接覆盖事实数据。
- [ ] 硬约束、知识权限、引用和拒答逻辑有自动化测试。

### 7.5 验证与证据

- [ ] 新增或修改逻辑包含正常、边界、异常和权限测试。
- [ ] PR 列出实际执行的命令、结果和必要截图。
- [ ] 测试数据可重复且已脱敏，不依赖作者机器的隐式状态。
- [ ] 至少一名非作者成员完成评审，所有阻断意见已处理。

## 8. 模块质量门禁

| 门禁 | 判断标准 | 未通过处理 |
|---|---|---|
| G1 模块需求覆盖 | 当前模块 P0 需求全部映射到任务、设计和验收场景 | 不进入 D2 设计与实现 |
| G2 模块设计稳定 | 当前模块的数据、接口、权限和工具契约评审通过 | 不开展模块内跨服务并行实现 |
| G3 公共基础可运行 | 新环境可启动，冒烟测试和日志链路通过 | 不开发依赖该基础的业务模块 |
| G4 安全基础 | 登录、用户隔离、授权和审计通过 | 不开放 AI 使用个人数据 |
| G5 确定性业务可信 | 无模型时模块基础功能可用，事实与硬约束测试通过 | 不接入本模块生成式能力 |
| G6 模块 AI 可控 | 引用、拒答、工具权限、降级和质量指标通过 | 不进入本模块完整端到端验收 |
| G7 模块验收关闭 | 对应 AT 场景通过，S1/S2 为 0，文档和追踪记录完整 | 不将模块标记为“已验收” |
| G8 发布候选 | AT-01～18 有证据，恢复演练通过，满足缺陷退出准则 | 不冻结最终演示版本 |

## 9. 需求追踪与过程留痕

每项需求至少维护以下链路：

```text
需求编号 → Issue/任务 → 设计或 ADR → 实现路径/PR
        → 自动化测试 → 人工验收记录 → 最终状态
```

状态统一使用：`待设计`、`开发中`、`待验收`、`已验收`、`受阻`。完成开发或变更合并后，应同步更新：

- `docs/process/TRACEABILITY_MATRIX.md`
- `docs/process/PROJECT_LOG.md`
- `docs/process/TEST_LOG.md`
- 受影响的需求、设计、接口或 ADR 文档

## 10. 风险驱动的重点复审项

| 风险 | 高风险位置 | 必须复审的证据 |
|---|---|---|
| 过敏或忌口误推荐 | 食堂过滤、条件解析、套餐合计、降级 | 硬约束单元测试、端到端反例、结果快照 |
| 学生数据越权 | 所有按用户查询、导出、历史记录和工具 | 双用户越权测试、审计事件、日志脱敏检查 |
| AI 编造校园规定 | 知识过滤、检索、提示、引用和拒答 | 标准问答集、无证据/冲突测试、引用定位 |
| 虚构馆藏状态 | 推荐合并、缓存、馆外数据和展示 | 数据库对账、馆藏/未收录分组测试 |
| 学习计划不可执行 | 时间计算、多考试优先级、信息缺失 | 总时长校验、边界日期和多考试用例 |
| 工具误用或提示注入 | Agent 路由、工具参数、身份透传 | 非法工具、越权参数、注入攻击测试 |
| 演示环境不稳定 | 依赖、模型网络、初始化与备份 | 全新启动、断网降级、重启和恢复记录 |

## 11. 完成定义（Definition of Done）

一个需求、模块或里程碑仅在以下条件全部满足时视为完成：

1. 需求验收标准已实现，未通过改变口径规避原需求。
2. 代码已合并到稳定分支，至少一名非作者完成评审。
3. 自动化测试通过，必要人工验收已记录环境、步骤、结果和证据。
4. 权限、隐私、日志、错误处理、AI 边界和降级路径已检查。
5. 数据迁移、接口兼容和失败恢复已按改动风险验证。
6. README、设计文档、ADR、项目日志和追踪矩阵已同步更新。
7. 不存在 S1/S2 缺陷；S3 缺陷有明确责任人和处理计划。
8. 功能能在团队约定的本地环境复现，并可纳入最终课堂演示。

## 12. 变更控制

需求、架构、数据库、公共接口、权限模型、Agent 工具或验收指标发生变化时，变更提交必须说明：变更原因、影响模块、兼容性、数据迁移、测试范围、回滚方式和文档更新位置。涉及个人信息、推荐硬约束、事实来源、提示注入防护或工具写入权限的变更，应由至少一名非作者进行专项安全复审。

# M01 公共工程契约

本文档固定 S1/M01 建立的跨端基础约定。后续模块必须复用这些约定；需要不兼容修改时，应先暂停当前模块并单独评审 M01 变更。

## 1. 统一响应

成功和失败响应均使用以下字段：

```json
{
  "success": true,
  "data": {},
  "error": null,
  "requestId": "8b7c...",
  "timestamp": "2026-08-30T12:00:00+08:00"
}
```

- `success`：请求是否完成。
- `data`：成功数据，失败时为 `null`。
- `error`：失败时包含稳定错误码和面向用户的消息，成功时为 `null`。
- `requestId`：跨浏览器、Java、Python 和日志传播的请求标识。
- `timestamp`：使用 `Asia/Shanghai` 时区的 ISO 8601 时间。

## 2. 错误码

| 错误码 | HTTP 状态 | 适用范围 |
|---|---:|---|
| `INVALID_REQUEST` | 400 | 参数格式、类型或约束错误 |
| `UPSTREAM_UNAVAILABLE` | 503 | Java、Python 或数据库依赖不可用 |
| `INTERNAL_ERROR` | 500 | 未分类内部异常；响应不得包含堆栈和配置值 |

业务模块只能增加自身错误码，不得改变以上公共语义。

## 3. 分页

分页从 `page=0` 开始，`size` 范围为 1～200。响应包含 `items`、`page`、`size`、`total` 和 `totalPages`。排序字段必须由服务端白名单限制，不能直接拼接客户端输入。

## 4. 请求标识

- 请求头和响应头统一使用 `X-Request-ID`。
- 调用方可传入 1～80 位字母、数字、点、下划线或连字符；非法值由入口服务替换为 UUID，防止日志注入。
- Java 调用 Python 时必须透传该值。后续工具调用继续复用同一标识。

## 5. 环境与配置

唯一可提交的环境模板为 `deploy/.env.example`，真实值写入被 Git 忽略的 `deploy/.env.local`。数据库地址、用户名、密码以及服务地址缺失时必须在启动阶段失败，不能静默使用生产式默认值。

## 6. 日志与脱敏

- 控制台日志至少包含时间、级别、服务、请求标识、记录器和消息。
- 不记录请求体、响应体、数据库连接串或异常中的配置值。
- `password`、`passwd`、`token`、`secret`、`api_key` 和 `authorization` 等赋值内容在输出前替换为 `***`。
- 当前 M01 只提供基础定位日志；跨服务指标和完整审计在 M09 实施。

## 7. 健康接口

- Java Actuator：`GET /actuator/health`。
- Python：`GET /health`，实际查询 PostgreSQL 和 pgvector 版本。
- 聚合链路：`GET /api/v1/health/system`，由 Java 同时检查自身数据库和 Python 服务。
- Web 首页只展示基础链路状态，不承载任何后续业务功能。

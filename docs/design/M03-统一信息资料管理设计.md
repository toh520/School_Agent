# M03 统一信息资料管理设计

- 阶段：S3
- 关联需求：FR-ADM-001～008
- 验收场景：AT-16、AT-18 的资料管理部分
- 开发状态：已完成并通过非作者验收

## 1. 模块边界

M03 只建设一个由 `INFO_ADMIN` 使用的统一资料管理后台，为后续模块提供可维护、可追踪的事实数据。学生不能访问管理接口，管理员也不能在该后台查看学生密码、令牌、私密对话或未授权个人数据。

本阶段不实现食堂推荐、考试规划、图书推荐、文档解析检索、智能问答或任何 Agent 工作流。

## 2. 资料分类与数据模型

| 资料类型 | PostgreSQL 表 | 主要关系与业务字段 |
|---|---|---|
| 食堂 | `canteen` | 编码、名称、位置、开放时间、说明、来源 |
| 窗口 | `food_stall` | 引用食堂编码，维护位置和供应时间 |
| 食材 | `ingredient` | 分类、口味、营养、过敏原、来源 |
| 菜品 | `dish` | 引用窗口和食材，维护价格、营养、口味、过敏原、供应时段及状态 |
| 书目 | `book` | ISBN、作者、出版社、版本、年份、标签、难度和来源 |
| 馆藏 | `library_holding` | 引用书目，维护索书号、位置、总册数、可借册数和状态 |
| 校园公告 | `knowledge_document` | 标题、类别、检索关键词、公告正文和信息来源 |
| 公共配置 | `system_config` | 只保存非敏感公共配置；密码、密钥和令牌必须使用环境变量 |

八类表采用统一治理字段：`id`、`code`、`name`、`status`、`source`、`created_by`、`updated_by`、`created_at`、`updated_at` 和 `deleted_at`。常用标识单独建列，类型差异字段存入受服务端 Schema 严格校验的 JSONB；表名只能由 `ResourceType` 白名单选择。

## 3. API 与权限

统一前缀为 `/api/v1/admin/management`，控制器级别要求 `ROLE_INFO_ADMIN`。

| 能力 | 方法与路径 |
|---|---|
| 字段 Schema 和 CSV 表头 | `GET /schemas` |
| 搜索、分页及状态筛选 | `GET /resources/{type}` |
| 新增、编辑、停用 | `POST /resources/{type}`、`PUT /resources/{type}/{id}`、`DELETE /resources/{type}/{id}` |
| CSV 预校验与确认入库 | `POST /imports/validate`、`POST /imports/commit` |
| 账号安全摘要和状态 | `GET /accounts`、`PATCH /accounts/{id}/status` |
| 管理操作记录 | `GET /operation-logs` |

默认列表只显示有效资料；前端可切换“有效资料/已停用资料”，并通过 `status=INACTIVE` 核查逻辑删除记录。资料、账号和操作记录统一按每页 20 条分页。存在有效子记录时禁止停用食堂、窗口或书目。管理员不能禁用自己的当前账号。重复资料编码返回 HTTP 409 冲突。

## 4. 校验与导入契约

- API、动态表单和 CSV 共用同一份服务端字段 Schema，字段分为必填、建议和可选。
- 校验覆盖唯一编码、必填、长度、URL、枚举、ISBN、非负数、馆藏数量及父子引用。
- 校园公告只维护可直接检索的文字信息；关键词按列表保存。本阶段不建立向量、不执行检索，也不调用大模型。
- CSV 必须为 UTF-8，最大 512KB、200 条数据；列表字段使用 `|` 分隔。
- 导入必须先预校验，错误精确返回行号、字段和原因；存在任一错误时整批不入库。
- 确认入库再次执行全部校验，并返回真实入库记录标识。
- 可重复模板位于 `docs/templates/m03/`。有父子关系时按食堂→窗口→食材→菜品、书目→馆藏的顺序导入，并按实际编码修改示例引用。

## 5. 可追踪性与安全

新增、编辑、停用、CSV 导入和账号状态变化写入 `admin_operation_log`，记录操作者、动作、资源类型、资源标识、资源编码、摘要、请求标识和时间。查询日志时关联安全账号摘要，前端显示操作者账号与用户标识、中文动作、作用对象和请求编号。操作日志不保存请求正文、密码、令牌或配置密钥。

V5 初始化数据均为脱敏的公开示例资料，不含真实学生身份。`system_config` 拒绝包含 `PASSWORD`、`SECRET`、`TOKEN`、`CREDENTIAL`、`PRIVATE_KEY` 或 `API_KEY` 的配置键，敏感值继续由 `code/deploy/.env.local` 提供且不得提交。

## 6. 前端信息架构

管理台采用“固定分类栏 + 资料画布”：餐饮、图书、校园资料和系统管理分组导航；每种资料使用统一搜索、列表、完整度刻度、动态表单和 CSV 导入流程。视觉沿用深海军蓝、青绿、纸白和金色标识，标题使用宋体风格，编码使用等宽字体。

页面覆盖加载、空数据、成功、错误、权限不足和确认操作状态，并适配 390px 移动端，不展示开发阶段、基础服务状态、Demo 或演示类文案。

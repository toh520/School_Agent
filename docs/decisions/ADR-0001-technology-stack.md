# ADR-0001：采用 Java 业务后端与 Python Agent 服务的组合架构

- 状态：已接受
- 日期：2026-08-27
- 关联范围：全部功能需求与非功能需求

## 背景

系统同时包含强事务校园业务、自然语言智能体、RAG 知识检索、学习分析和高并发服务。单一技术运行时难以同时兼顾业务规则一致性、AI 生态、团队协作和生产运维。

## 决策

- 前端采用 Vue 3、TypeScript、Vite 和 Element Plus。
- Java 21 + Spring Boot 3.5 负责身份权限、食堂与食材、考试记录与学习计划、图书馆馆藏、知识元数据和审计等确定性业务。
- Python + FastAPI + LangGraph 负责对话、食堂推荐、学习规划、书籍推荐、RAG 问答、模型调用和 Agent 编排。
- Agent 只能通过经过授权、参数校验和审计的工具接口访问业务能力，不直接修改核心业务表。
- PostgreSQL 为业务事实数据源，pgvector 保存知识向量；Redis、RabbitMQ 和 MinIO 分别承担缓存/限流、异步任务和对象存储。
- 生产环境采用 Kubernetes，使用 Prometheus、Grafana 和 OpenTelemetry 建立指标、日志和链路追踪。

## 影响

- 优点：业务边界清晰，事务逻辑稳定，可充分利用 Python AI 生态，并支持各服务独立扩缩容和故障隔离。
- 代价：存在跨语言接口、分布式追踪、部署和数据一致性复杂度，需要统一契约测试和可观测性规范。
- 约束：Python Agent 不得绕过 Java 业务服务修改核心数据；敏感操作必须确认、授权和审计。

## 替代方案

- 全部采用 Python：AI 开发简单，但复杂事务、权限和长期大型业务维护风险更高。
- 全部采用 Java：业务治理统一，但 Agent/RAG 生态接入和实验效率较低。
- 模块化单体：适合早期业务开发，但 AI 任务、流式响应和高峰资源隔离能力不足；可作为部分 Java 服务的内部组织方式，而非取消服务边界。

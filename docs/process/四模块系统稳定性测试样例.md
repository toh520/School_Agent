# 智慧校园四模块人工稳定性测试样例

> 适用模块：智能食堂、校园助手、智能图书馆、考试助手
> 基准账号：本地学生账号 `student1 / Student@123`
> 测试日期：执行时填写
> 说明：AI 输出具有随机性，验收应检查“事实、约束、来源、状态和数据一致性”，不要要求回答逐字一致。

## 1. 执行准备与统一判定标准

### 1.1 前置条件

1. 执行 `./code/tools/start-dev.ps1`，确认 Web、Java、Agent 和 PostgreSQL 均启动成功。
2. 使用学生账号登录。若要测试过敏原，先在个人中心把“蛋类、奶类、甲壳类”依次加入或移除，并记录每次测试使用的档案。
3. 若要测试练习、错题本和复习计划，分别开启“练习与错题记录”和“考试与学习计划”授权。
4. 已导入仓库自带演示数据；涉及馆藏数量、考试日期的预期结果以当前页面显示值为基准。
5. 每条用例执行后记录：通过/失败、响应耗时、错误提示、是否出现重复数据、页面是否卡死、刷新后数据是否一致。

### 1.2 通过标准

- 单次普通查询页面不白屏、不无限加载、不出现未处理异常；AI 请求超时或失败时有明确提示且可以再次操作。
- 所有硬约束均生效：预算、过敏原、排除食材、库存、授权和用户数据隔离不得被 AI 文本绕过。
- 数据写入操作只发生一次；连续点击、刷新或重试不得产生重复订单、重复借阅或异常库存。
- AI 不得编造数据库中的菜品、库存、考试安排或校园制度；证据不足时明确说明限制。
- 切换页面或刷新后，已成功保存的数据仍一致；失败请求不得留下半成品数据。

## 3. 校园助手

以下文字均可直接粘贴到校园助手输入框。校园知识演示库目前较精简，因此事实型问题的关键验收点是“命中则展示依据，未命中则承认资料不足”。

| ID | 输入/操作 | 预期结果 |
|---|---|---|
| CAMPUS-01 | `校园公共服务有哪些基础说明？` | 回答引用命中的校园服务资料或明确说明资料内容有限，显示依据/限制。 |
| CAMPUS-02 | `图书馆开放时间是什么？` | 若当前知识库仅有“以最新公告为准”，不得编造具体时段；应提示以最新公告为准并展示来源。 |
| CAMPUS-03 | `校园卡丢失后应该如何补办？` | 无可靠资料时明确未命中或仅给一般参考，不编造具体地点、费用、电话。 |
| CAMPUS-04 | `学校奖学金申请需要什么材料？` | 未命中时不得生成看似确定的本校材料清单；提示咨询责任部门或补充资料。 |
| CAMPUS-05 | `学生证明可以在哪里办理？` | 不确定信息必须带限制，不虚构办公地点和办理时间。 |
| CAMPUS-06 | 首轮：`图书馆开放时间是什么？`；次轮：`周末呢？` | 次轮能承接“图书馆开放时间”上下文；仍受资料证据约束。 |
| CAMPUS-07 | 首轮：`校园卡丢了怎么办？`；次轮：`需要带什么材料？`；三轮：`如果人在校外呢？` | 三轮主题连续，不重复丢失上下文，不把推测表述为校规。 |

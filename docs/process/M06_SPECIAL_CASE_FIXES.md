## 修复后的再次测试与 GitHub 参考

第一轮修复后的扩展真实测试仍发现新问题，继续修复，没有把 HTTP 200 当作内容正确：

1. 二分查找第三轮追问答对0次，但模型编造 `trustedChecks` 内部字段，并混淆教材证据与程序规则，导致拦截。改为由程序生成次数校验说明；保留候选数值原样校验，错误次数仍拒绝。明确教材缺少直接论述与程序规则成立并不矛盾。
2. 一道程序练习输入 `5 / ABCDE / CBADE` 的层序样例误写为 `ABCDE`，实际应为 `ABDCE`。增加针对明确 `n / 先序 / 中序 → 层序` 协议的独立重建与广度遍历参考算法，保存前核对样例，错误触发重新生成。本轮错误测试题 `337460f8-b5b4-4f8a-9680-b728339c29d8` 的第2个样例已定点修正，其他记录不变；原始内容保留在本地扩展测试日志。
3. 定向重复中出现递归基础例题允许1000节点，以及单个互异大写字母与1000节点上限矛盾。该类树重建基础程序练习增加1≤n≤26的生成要求和已识别输入协议的上限校验，本轮两条测试题题干仅定点修正上限；不扩展为任意语言/算法的执行安全保证。同时增加最终响应测试，确保审查模型不能覆盖程序拥有的次数校验说明。
4. 次数正确但步骤声称标准二分查找要求非空，或将空数组视为非法输入。增加概念一致性规则和明确提示：空数组是可处理边界，初始区间为空，循环不进入，比较0次。

按用户要求查阅公开 GitHub 项目，只读研究，没有安装、执行或复制外部项目代码：

- [OATutor/checkAnswer.js](https://github.com/CAHLR/OATutor/blob/main/src/platform-logic/checkAnswer.js)：按答案类型使用字符串、数值及符号比较，返回校验结果与错误原因。参考的是“明确算法负责校验、反馈另行组织”的职责划分；本项目并未引入其符号计算器，也不能据此宣称支持通用数学证明。
- [tutor-agent/quiz_tools.py](https://github.com/ghdkim/tutor-agent/blob/main/tools/quiz_tools.py)：将题干、选项、正确答案和讲解分为结构化字段。其部分约束只是字段描述，不是完整的业务校验；本项目继续保留选项唯一性、答案归属、分数一致性等硬校验，没有照搬其模型或架构。

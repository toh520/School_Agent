## 一、真实请求确认的问题（建议优先修复）

### P1：无作答过程时仍给确定性错因，矛盾答案被判为资料支持

题目：根A、左B、右C，求前序。用户作答过程为“我只记得最后写了BAC，其他过程完全没有写，也不记得怎么想的”。

两次真实请求均出现：

- `answer`为`BAC`，步骤和结论却给出`ABC`，展示字段互相矛盾。
- 将错因确定为“混淆前序与中序”，并未承认无法从缺失过程确定真实原因。
- 返回`MATERIAL_SUPPORTED`，独立审查未拦截。
- `correctedPoints`谈到“原回答错误/原回答正确”，但本轮没有提供原AI回答，仍混淆用户作答和旧回答。

期望：可以说明BAC与前序规则不符，但只能把混淆中序列为可能原因；要求补充过程，不能作确定性诊断。所有展示字段需一致。资料支持前序定义，不等于支持对用户心理或作答原因的断言。

### P1：条件变更后旧二分查找规则反而阻止正确回答

原题含“长度为16”，最新纠正为“把数组大小改为32”。两次真实请求均被拦截，错误提示仍要求最坏比较次数为5；按本题闭区间、三路比较口径应为6。

另一次将条件改成空数组，也因结构化次数仍为5而被拦截，无法正常答复0次。

原因：`reference_checks()`拼接旧题与纠正后，仅识别“长度+数字”，无法处理“大小32”或“空数组”对旧条件的覆盖。属于程序规则误用，不是用户缺少题目条件。

### P2：自测请求换一种说法就误拦截

- 中文“出一道二叉树前序遍历自测题，先别告诉我答案……”：两次均返回`NEEDS_CLARIFICATION`，局限为“模型返回缺少字段: answer”。
- 英文“Give me one binary tree preorder traversal practice question without the answer or solution steps.”：同样误拦截。

受控检查也显示`question_only()`只识别较窄的中文关键词组合；“仅提供一道练习，暂时隐藏解答”也不进入专门保护。模型按提示生成自测专用字段，但程序没有识别到对应模式，造成协议不一致。本轮真实结果为误拦截，并非已观察到这两种说法泄露答案；保护缺口仍存在。

# 项目过程日志

本文件从当前项目初始基线开始记录关键活动。日常代码变更以 Git 提交和 Pull Request 为准；涉及需求范围、架构、安全、验收或计划的重要事件同时记录在此。

## 2026-08-28｜简化知识资料处理与基础账号要求

- 背景：项目以本地课设展示和功能闭环为重点，不建设面向真实生产环境的复杂内容解析与安全治理体系。
- 知识资料：仅保留管理员手工录入以及 Markdown、TXT 纯文本导入；取消 DOCX、网页、PDF、表格和页码定位等复杂解析要求。
- 知识问答：使用基础文本切分和关键词或向量检索，来源简化为资料名称及可选链接，资料管理简化为启用和停用。
- 账号与数据：保留本地账号登录、基础单向密码哈希、学生/管理员角色区分和学生数据隔离；取消统一认证、独立授权中心、长期记忆治理和复杂审计平台。
- 安全边界：使用虚拟演示数据和本地密钥配置，不把 TLS、字段加密、专项 Web 攻击防护、导出审批等工业级措施作为课设验收要求。
- 验收调整：AT-15 由授权撤回改为 Markdown、TXT 简单资料导入，追踪矩阵同步调整。
- 验证：执行 Markdown 差异检查和关键词一致性检查，确认需求、数据、界面、接口、验收与风险描述保持一致。

## 2026-08-27｜确定 V1.0 课设范围

- 需求基线：将当前 Markdown 定义为 V1.0。
- 管理方式：合并为一个信息资料管理员和一个统一管理后台，集中维护全部基础信息，并强调录入完整度。
- 考试记录：只录入科目、考试时间和备注，由系统自动排序并展示最近考试，不调用 AI。
- AI 规划：学生主动请求后，AI 再进行必要追问并调用考试、资料、书籍和计划计算工具，生成基础复习计划书。
- MVP 边界：实现计划书生成、保存、查看、删除和重新生成；任务勾选、进度跟踪与动态重排作为后续扩展。
- 运行方式：开发阶段仅要求本地测试和课堂演示，个人云服务器部署可选，不建设工业级集群、复杂监控和容灾体系。
- 验证：检查需求编号、角色一致性、考试字段、MVP 边界、部署描述和活动文档同步情况。

## 2026-08-27｜建立项目初始基线

- 项目范围：面向学生的智慧校园 AI 助手。
- 基础能力：登录、账户、个人偏好、授权、权限和审计。
- 核心功能：智能食堂推荐、考试安排与 AI 学习规划、学校书籍查询推荐、校园知识问答。
- 正式需求：`docs/requirements/智慧校园智能体系统需求分析报告.md`。
- 协作规则：代码应包含必要注释并按职责结构化组织；Git 提交应记录背景、主要变更、影响和验证结果。
- 初始状态：当前仓库文件作为项目开发起点，不包含早期需求版本、生成工具或历史过程记录。
- 验证要求：检查 Markdown 结构、需求编号、仓库链接、Git 差异和工作区状态后建立根提交。

- UTF-8 CSV 模板、预校验、行/字段错误清单、整批阻断和确认入库；
- 安全账号摘要、账号启停、自禁用保护和管理操作记录；
- PostgreSQL V5 表结构及 V6 校园公告简化迁移、索引、外键、逻辑删除和脱敏初始化数据；
- Java、前端隔离和真实链路自动化测试。

## 3. 非作者验收步骤

1. 在 VS Code 打开仓库根目录，确认当前分支为 `feature/m03-information-management`，执行 `conda activate school-agent`。
2. 在 PowerShell 执行 `./code/tools/test-all.ps1`，确认 Java 26/26、pytest 5/5、隔离 Playwright 9/9，且构建成功。
3. 执行 `./code/tools/start-dev.ps1`，看到完整健康链路成功后访问 <http://127.0.0.1:5173/>。
4. 使用本地管理员 `admin1` / `Admin@123` 登录；确认出现“校园资料管理台”，且能在食堂、窗口、食材、菜品、书目、馆藏、校园公告、公共配置、账号状态和操作记录之间切换。
5. 在“食堂”新增一条唯一编码资料，故意漏掉必填字段确认表单阻止保存；填写完整后保存，再通过编码搜索、编辑名称并停用；用同一编码再次新增时确认接口提示冲突。
6. 在资料状态中切换“有效资料/已停用资料”，确认停用记录只出现在停用列表；当数据超过 20 条时，切换页码并确认列表和总数正确。
7. 打开“操作记录”，确认新增、编辑、停用均显示中文动作、操作内容、管理员账号与用户标识、资料类型与编码、请求编号和时间；当日志超过 20 条时确认分页可切换。
8. 在“食材”打开批量导入，先上传含负数热量的 CSV，确认错误精确指向第 2 行 `nutritionKcal` 且“确认入库”不可用；修正后重新预校验并确认入库。
9. 按 `docs/templates/m03/` 查看八类模板；父子数据按食堂→窗口→食材→菜品、书目→馆藏顺序测试。
10. 退出管理员并以 `student1` / `Student@123` 登录，确认只能进入个人中心，无法看到管理台；执行真实测试进一步确认管理 API 返回 403。
11. 在 VS Code Database Client 中连接 `127.0.0.1:5432/school_agent`，查看八类资料表和 `admin_operation_log`；确认不存在密码明文、JWT 或学生私密正文。
12. 在 Web 目录执行 `npm run test:e2e:live`，确认 7/7；验收结束后可在仓库根目录执行 `./code/tools/stop-dev.ps1`。
